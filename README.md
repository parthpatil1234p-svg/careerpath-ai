4. **Disconnection from Hiring Realities:** Students study theoretical concepts without knowing verified Indian salary benchmarks (₹ CTC) or live employer vacancies.

## 🧠 Explainable Career Matching Engine (100% Transparent Math)

One of CareerPath AI's most critical innovations is **Explainable AI (XAI)**. We firmly reject the practice of feeding student profiles into black-box LLMs and hoping for reasonable output. Instead, our recommendation engine (`server/services/recommendationService.js`) calculates match scores through a **deterministic mathematical scoring matrix**.

### 3.1 The 60/25/15 Mathematical Formulation

The overall Career Match Score is computed using an objective weighted linear model:

$$\text{Career Match Score} = (\text{Skill Match Score} \times 0.60) + (\text{Interest Match Score} \times 0.25) + (\text{Education Match Score} \times 0.15)$$

Where:
- **Skill Match Score ($S$ — 60% Weight):** Represents the student's technical capability against the career's curriculum.
- **Interest Match Score ($I$ — 25% Weight):** Measures alignment between student passions and role domain tags.
- **Education Match Score ($E$ — 15% Weight):** Measures academic branch and degree fit.

```
                      CAREER MATCH SCORE (0 - 100%)
┌───────────────────────────────────────┬───────────────────┬──────────────┐
│       SKILL MATCH SCORE (60%)         │  INTEREST (25%)   │  EDU (15%)   │
│  Weighted by Importance & Confidence  │ Jaccard Overlap   │ Degree Match │
└───────────────────────────────────────┴───────────────────┴──────────────┘
```

#### Detailed Skill Match Formula
Each required skill in a career profile has an **Importance Weight** ($W_i$) and a **Required Proficiency** ($R_i$):

$$\text{Importance Weight } (W_i) = \begin{cases} 3 & \text{if importance is 'high'} \\ 2 & \text{if importance is 'medium'} \\ 1 & \text{if importance is 'low'} \end{cases}$$

$$\text{Proficiency Value } (P) = \begin{cases} 3 & \text{if 'advanced'} \\ 2 & \text{if 'intermediate'} \\ 1 & \text{if 'beginner'} \end{cases}$$

For every required skill, we compute the **Proficiency Ratio** ($PR_i$) and multiply it by the **Skill Passport Confidence Weight** ($C_i$):

$$PR_i = \min\left(\frac{P_{\text{user}}}{P_{\text{required}}}, 1.0\right)$$

$$\text{Weighted Earned Points } (WE_i) = W_i \times PR_i \times C_i$$

The total Skill Match Score is normalized to a percentage:

$$\text{Skill Match Score} = \left(\frac{\sum WE_i}{\sum W_i}\right) \times 100$$

*(Note: The ratio is strictly capped at $1.0$. Over-qualification in one skill does not artificially inflate or mask deficiencies in other critical skills).*

---

### 3.2 4-Tier Skill Passport Confidence Multipliers

To prevent unverified self-ratings from swaying recommendations unfairly, CareerPath AI applies a **4-Tier Confidence Multiplier** ($C_i$) to every skill:

| Passport Tier | Verification Method | Confidence Multiplier ($C_i$) | Description & Rationale |
| :--- | :--- | :---: | :--- |
| **Tier 0: Self-Rated** | Form submission only | **0.70** | Unverified claims receive a 30% discount to reflect self-reporting bias |
| **Tier 1: Quiz-Verified** | Groq / Gemini Micro-Quiz | **0.85** | Passed dynamic 5-question technical reality-check assessment |
| **Tier 2: Code-Verified** | GitHub AST Session Sync | **1.00** | Real production code scanned from public repositories (full 100% credit) |
| **Tier 3: Interview-Verified** | Spoken Technical Interview | **1.05** | Bonus credit for passing deep verbal technical evaluation |

### 3.3 Step-by-Step Worked Mathematical Calculation Example

Let us trace an actual student, **Aarav**, being evaluated for the **Full-Stack Developer** role.

#### Step 1: Career Requirements Profile (Full-Stack Developer)
The role requires 4 skills:
1. **JavaScript:** Importance = High ($W_1 = 3$), Required = Advanced ($R_1 = 3$)
2. **React:** Importance = High ($W_2 = 3$), Required = Intermediate ($R_2 = 2$)
3. **Node.js:** Importance = Medium ($W_3 = 2$), Required = Intermediate ($R_3 = 2$)
4. **Docker:** Importance = Low ($W_4 = 1$), Required = Beginner ($R_4 = 1$)

$$\text{Total Importance Weights} = 3 + 3 + 2 + 1 = 9$$

#### Step 2: Student Qualifications (Aarav's Profile)
- **JavaScript:** User level = Advanced ($P = 3$). Verified via GitHub Code Sync $\rightarrow C_1 = 1.00$.  
  $$WE_1 = 3 \times \min\left(\frac{3}{3}, 1\right) \times 1.00 = 3 \times 1.0 \times 1.00 = 3.00$$
- **React:** User level = Beginner ($P = 1$). Verified via Quiz $\rightarrow C_2 = 0.85$.  
  $$WE_2 = 3 \times \min\left(\frac{1}{2}, 1\right) \times 0.85 = 3 \times 0.5 \times 0.85 = 1.275$$
- **Node.js:** User level = Intermediate ($P = 2$). Self-rated only $\rightarrow C_3 = 0.70$.  
  $$WE_3 = 2 \times \min\left(\frac{2}{2}, 1\right) \times 0.70 = 2 \times 1.0 \times 0.70 = 1.40$$
- **Docker:** Missing from user profile $\rightarrow P = 0$.  
  $$WE_4 = 1 \times 0 \times 0.70 = 0.00$$

$$\text{Total Weighted Earned Points} = 3.00 + 1.275 + 1.40 + 0 = 5.675$$

$$\text{Skill Match Score} = \left(\frac{5.675}{9}\right) \times 100 = 63.05\%$$

#### Step 3: Interest Match Score
- Career interest tags: `["web development", "backend", "cloud architecture", "system design"]` (4 tags).
- Aarav declared interests: `["web development", "cloud architecture", "machine learning"]`.
- Overlapping tags = 2 (`web development`, `cloud architecture`).

$$\text{Interest Match Score} = \left(\frac{2}{4}\right) \times 100 = 50.0\%$$

#### Step 4: Education Match Score
- Aarav's degree: `B.Tech in Computer Science`.
- Career preference: `["Computer Science", "Information Technology", "BCA", "MCA"]`.
- Matches preferred degree $\rightarrow$ **100% Match**.

$$\text{Education Match Score} = 100.0\%$$

#### Step 5: Final Weighted Career Match Score
$$\text{Final Score} = (63.05 \times 0.60) + (50.0 \times 0.25) + (100.0 \times 0.15)$$
$$\text{Final Score} = 37.83 + 12.50 + 15.00 = \mathbf{65.33\%} \rightarrow \mathbf{65\%}$$

**Result:** Aarav receives a **65% Match** for Full-Stack Developer, complete with the transparent mathematical breakdown and exact skill gaps!

### 3.4 Primary Stream Isolation (No Foreign Stream Spillover)

A common flaw in generic career apps is recommending technical coding jobs to Commerce, Arts, or Business students who lack foundational technical interest. CareerPath AI implements **Strict Primary Stream Isolation**:
1. During profile assessment, the student's declared or auto-inferred **Primary Stream** is resolved:
   - `Engineering & Tech` (B.Tech, BCA, MCA, CS, IT)
   - `Business & Management` (BBA, B.Com, MBA, Finance, Economics)
   - `Marketing & Communications` (Marketing, Media, PR)
   - `Design & Creative` (UI/UX, Animation, Fine Arts)
2. In `services/recommendationService.js`, if a student selects a specific stream, candidate careers are **strictly filtered to that domain before scoring**. Foreign stream careers are never scored or suggested unless the student explicitly selects "Explore All Streams".

### 3.5 Deterministic Natural Language Explanations (Zero Hallucinations)

Every recommendation displays a plain-English explanation generated **without calling external LLM APIs**. The explanation engine (`generateExplanation` in `recommendationService.js`) dynamically composes a structured explanation:
- **Tone Calibration:** Sets confidence level based on score (≥75%: *"Strong match with high alignment"*; ≥50%: *"Good potential match"*).
- **Competence Acknowledgement:** Specifically cites matched verified skills (e.g. *"You already have strong competence in JavaScript and HTML."*).
- **High-Priority Guidance:** Pinpoints high-importance missing skills to focus on next (e.g. *"To become fully job-ready as a Full-Stack Developer, focus next on mastering Docker and Express."*).

## 🗺️ Hardened Single Active Career Route Architecture

### 5.1 The Tutorial-Hopping Dilemma & DB Invariant
Online learners frequently drop out because they enroll in 5 different tracks simultaneously, completing 5% of each and mastering none. In multi-tab browsing or rapid clicking, race conditions can also generate duplicate active roadmaps.

To solve this, CareerPath AI enforces a **Single Active Route Invariant** at the database engine level.

### 5.2 MongoDB Partial Unique Index (`status: 'active'`)
```javascript
// server/models/Roadmap.js
RoadmapSchema.index(
  { user: 1 },
  { 
    unique: true, 
    partialFilterExpression: { status: 'active' } 
  }
);
```
- **Guaranteed Singularity:** A student can have at most **one** roadmap with `status: 'active'`.
- **Concurrency Immune:** If concurrent requests bypass the API controller, MongoDB throws error `E11000 duplicate key error`.
- **Historical Flexibility:** A student can possess unlimited roadmaps with `status: 'completed'`, `'abandoned'`, or `'archived'`.

### 5.3 Non-Destructive 7-Day Rate-Limited Abandonment
Students are not locked into a career indefinitely, but abandonment is treated with intentional discipline:
1. **7-Day Rate-Limiting Cooldown:** `User.lastAbandonedRouteAt` tracks abandonment. If a student attempts to abandon again within 7 days, the request returns `HTTP 429 ABANDON_COOLDOWN_ACTIVE`.
2. **Zero Progress Loss Guarantee:** Abandoning updates roadmap status to `'abandoned'`. All weekly milestone test scores, task checkboxes, and verified skill badges are **100% preserved**.
3. **Resumption:** An abandoned roadmap can be resumed anytime via `POST /api/roadmaps/:id/resume`, provided the student has no active route.

### 5.4 "Lock Enrolling, Never Browsing" UI Paradigm
On `/recommendations.html`:
- **Exploration is 100% Unlocked:** Students can freely inspect requirements, review full skill-gap breakdowns, test the interactive What-If Simulator, and inspect Live Market Jobs on any career card.
- **Enrolment is Strictly Gated:** Other career tracks show a sleek, accessible locked action:
  ```html

    <i class="bi bi-lock-fill me-1"></i> Locked (Active Route Enrolled)
  </button>
  ```
- **High-Contrast Slate Aesthetics (`.cp-btn-locked`):** Uses `#475569` text on a `#F1F5F9` slate background with `#CBD5E1` border—replacing legacy dark-grey-with-blue-text buttons with 100% WCAG AA compliant contrast.
- **Single Horizontal Baseline Alignment:** Sibling buttons (`⚡ What-If Simulator`, `💼 Live Market Jobs`, and `🔒 Locked (Active Route Enrolled)`) share identical sizing (`btn-sm px-3 py-2 fw-semibold`) and perfect horizontal alignment without dangling text.
- **Artifact-Free Vector SVG Rendering:** Card hover animations are scoped cleanly to interactive elements, completely eliminating fuzzy `drop-shadow` blur halos and hardware-accelerated bounding box artifacts.

## 📄 Dedicated Single Resume per Account Architecture

### 7.1 Binary Magic-Byte Inspection (`%PDF`, `DOCX`, `DOC`)
File extensions and HTTP `Content-Type` headers can easily be spoofed by attackers renaming executables to `.pdf`. `server/controllers/userController.js` inspects the leading **magic bytes** of the binary buffer:

| Format | Magic Bytes (Hex) | ASCII Signature | Description |
| :--- | :--- | :--- | :--- |
| **PDF** | `25 50 44 46` | `%PDF` | Adobe Portable Document Format |
| **DOCX** | `50 4B 03 04` | `PK..` | Modern Office OpenXML ZIP archive |
| **DOC** | `D0 CF 11 E0` | `....` | Legacy Microsoft Compound Document |

Files with invalid signatures are rejected immediately with `HTTP 400 INVALID_FILE_SIGNATURE`.

### 7.2 Transactional Cloudinary Asset Destruction (Zero Leakage)
To prevent orphaned cloud files from inflating storage quotas:
1. Validate file size (max 5MB) and binary magic bytes.
2. Upload new buffer to Cloudinary CDN (`resource_type: 'raw'`).
3. If an existing resume exists:
   - Transactionally destroy the previous asset on Cloudinary (`cloudinary.uploader.destroy`).
   - Update MongoDB `Resume` document with the new URL and metadata.
4. If upload fails, previous assets and records remain completely untouched.

### 7.3 6-State Interactive Dashboard Experience
The resume widget on `/dashboard.html` features 6 fluid states:
1. **Empty State:** Drag-and-drop zone with format chips.
2. **Uploading State:** Real-time animated progress bar.
3. **Active State:** File icon, filename, size, upload date, and View/Download actions.
4. **Confirm Replace Modal:** Explicit confirmation before replacing an existing resume.
5. **Confirm Delete Modal:** Safe confirmation before cloud asset destruction.
6. **Error / Toast State:** Instant feedback on oversized files (>5MB) or invalid signatures.

## 🔒 Security, Guardrails & Anti-Abuse Protocols

1. **Strict Content Security Policy & Headers:** Enforced via `helmet` across all REST responses.
2. **CORS Isolation:** Backend strictly restricts origins to production frontend (`https://careerpath-ai-jade.vercel.app`) and local development ports (`http://localhost:5500`, `http://127.0.0.1:5500`).
3. **Password Security:** Salted 10-round hashing via `bcryptjs`. Plaintext passwords are never logged or stored.
4. **Binary Protection:** Magic-byte validation rejects malicious executables renamed as `.pdf` or `.docx`.
5. **Rate Limiting:**
   - Auth endpoints: Max 10 requests per 15-minute window per IP.
   - AI endpoints: Max 30 requests per minute per IP.
   - Abandonment endpoint: Strictly limited to 1 abandonment per 7 days per account.
